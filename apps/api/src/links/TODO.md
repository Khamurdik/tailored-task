# links — L3

## Purpose
Turns a URL a stranger was handed into a grant. The only anonymous, unguarded,
attacker-reachable surface in the API, and the only place short share codes are
minted or read.

## Owns
No table and no minting. Credentials live on `access`'s `shares` row and are
issued by `access`'s `ShareCodec`. What this module owns is the **anonymous
edge**: the resolve route, its throttle, its redaction, and the guarantee that
every way of failing looks the same.

## Public surface
- `LinksController`
  - `GET /shares/resolve` — anonymous. `X-Share-Token: <token | code>` →
    `{ rootNodeId, role, expiresAt }`, or a uniform 404

## Depends on
`common`, `access` (`SharesRepository`, `ShareCodec`).

## Must not depend on
`sharing` — it sits beside this module in L3, not below it, and nothing here
needs it. `files`, `jobs`. `nodes` is deliberately absent too; see *What resolve
returns*.

Minting lives in `access` rather than here for the same reason the `shares`
table does: `sharing` must issue a credential and this module must read one, and
if either owned the format the other would be importing sideways. Both import
downward instead. The format below is the **specification**; `access` is where
it is implemented, next to the columns it fills.

## Why this is not part of `sharing`

Same reasoning that split `access` from `sharing`, applied to the HTTP edge
instead of the data model.

Every route in `sharing` is owner-authenticated and guarded by
`@RequireAccess('own')`. Every route here is **anonymous by design** and takes
an attacker-controlled, enumerable string as its entire input. Those are
opposite defaults, and a controller holding both is exactly where a missing
guard hides — the reviewer's eye reads "this file is the owner API" and skips
the one method that isn't.

Keeping them apart buys three things that are otherwise conventions:

1. The throttle, the uniform 404, and the entropy policy live in one auditable
   file rather than being properties someone remembered to apply.
2. `sharing` can be tested as "owner-only, no exceptions" — a suite can assert
   that *every* route it exposes rejects an anonymous caller, with no carve-out.
3. The two have different reasons to change. `sharing` changes when the rules
   about who may be granted access change; `links` changes when the format of a
   URL changes.

Neither module owns state, both wrap `SharesRepository`, and neither imports the
other. The layer graph is unchanged.

## Credentials — two, and the second is opt-in

A grant may be reachable by two strings. Both are bearer credentials, both are
stored as SHA-256, both are revoked by revoking the grant.

| | Length | Entropy | Default |
| --- | --- | --- | --- |
| **Token** | 43 chars (32 bytes, base64url) | 256 bits | always minted |
| **Short code** | 16 chars (Crockford base32) | 80 bits | **off** — `shortLink: true` on create |

`access` stores them as `token_hash` and `short_code_hash`, both unique, both
nullable for the code. Two columns on the row that already exists, not a second
table: a short code is not an object with a lifecycle of its own, it is a second
spelling of one grant, and giving it its own table would create a second place
to remember to revoke.

### Why short codes are opt-in rather than always on

**A grant is only as strong as its weakest credential.** Minting a code takes a
share from 256 bits to 80 the moment it exists, and doing that to every share by
default would quietly re-price the security of the whole product to buy
readability on the links that happen to be pasted into chat.

80 bits is not a compromise, though — it is unguessable by any practical means
(at a million attempts per second it is ~38 million years to a 50% hit, and the
throttle below caps it far lower). The floor is **64 bits**; below that, the
per-IP rate limit stops being a comfortable margin and starts being the only
thing holding, and a rate limit is a control that can be misconfigured.

### Code format
- [ ] **Crockford base32**, 16 characters. No `I`, `L`, `O`, or `U`, so a code
      read off a screen and retyped cannot land on a different valid code by
      transcription. `U` is excluded to keep accidental words out of codes
- [ ] Decode case-insensitively and map `I`/`l` → `1`, `O` → `0` on input, per
      Crockford. Emit uppercase, always
- [ ] No checksum character. It would leak a cheap validity oracle: an attacker
      could filter guesses offline before spending a request against the
      throttle
- [ ] The code is generated by `crypto.randomBytes`, never from the share id,
      the node id, a counter, or a timestamp. A derivable code is not a
      credential

## Responsibilities

- [ ] `GET /shares/resolve` — reads `X-Share-Token`, resolves it as a token
      *or* a short code, returns `{ rootNodeId, role, expiresAt }`
- [ ] Look the credential up **by hash**, never by scanning. One indexed query
      against `token_hash`, one against `short_code_hash`, and the second only
      runs if the input is 16 characters — a 43-char token cannot be a code
- [ ] Constant work on failure: an unknown credential must not be measurably
      faster than a revoked one. Both paths hash the input and hit the index
- [ ] `@nestjs/throttler` keyed by IP, tight. This endpoint is the guessing
      surface for every share in the system, and no legitimate visitor resolves
      more than a handful of links a minute
- [ ] `Referrer-Policy: no-referrer` and `Cache-Control: no-store` on the
      response. The credential is in a request header here, but the *page* that
      called this endpoint has it in its URL, and any third-party request from
      that page leaks it in `Referer`

### What resolve returns, and what it deliberately does not

```ts
{ rootNodeId: string; role: 'viewer'; expiresAt: string | null }
```

It does **not** include the node's name, type, or child count, even though
`public-view` renders all three and will therefore make a second request for
`GET /nodes/:rootNodeId` with the same header.

That second request is the point. Inlining a node summary here would mean this
module reads the tree, which means the anonymous path grows a second way to
learn about a node — one that did not go through `NodeAccessGuard`. Every fact a
visitor learns about the tree should come through the same guard the owner's
requests go through, and the cost of that rule is one extra round trip on one
page load.

## Invariants
- **Every failure is identical.** Unknown, malformed, revoked, expired, and
  pointing-at-a-deleted-node all return the same status, the same body, and the
  same headers. This is the API half of the one-screen decision in
  [`public-view/TODO.md`](../../../web/src/features/public-view/TODO.md); a
  distinguishable API makes the single screen cosmetic.
- No response from this module ever contains a plaintext token or code — not in
  a body, not in a header, not in an error.
- Nothing here is logged with the credential in it. The request logger must
  redact `X-Share-Token` for this route, and the code must never appear in a
  URL path the server logs. That is why the credential travels in a header even
  though the browser-facing route is `/s/:code`: the **web app** reads the code
  out of its own URL and sends it as a header, so it never reaches an access log.
- Resolution never issues a session. A visitor holding a code stays anonymous;
  the code is presented on every request.
- This module never creates, mutates, or revokes a grant. It reads.

## Tests

> These are the **requirements**. They are declared as addressable, traceable tests in
> [`tests/suites/api/links/TODO.md`](../../../../tests/suites/api/links/TODO.md) and implemented there — never in this module's folder.
- [ ] Resolving a valid token and a valid short code for the same share returns
      byte-identical bodies
- [ ] Unknown, revoked, expired, and deleted-target all return byte-identical
      responses — the single highest-value test in this module
- [ ] A minted code is 16 Crockford characters and contains no `I`, `L`, `O`, `U`
- [ ] Two thousand mints produce no duplicate and no derivable pattern
- [ ] Revoking the share kills both the token and the code in the same request
- [ ] A share created without `shortLink` has no code, and its share row's
      `short_code_hash` is null

## Done when
A 19-character URL opens a share in a fresh incognito window, the same share's
43-character URL opens it too, revoking once kills both, and every way of
getting it wrong produces one indistinguishable 404.
